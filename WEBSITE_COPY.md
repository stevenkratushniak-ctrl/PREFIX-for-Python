## The Problem

Python teams do not lose time only because code is wrong.

They lose time because mutation is often unclear, unreplayable, and discovered too late.

Common failure loops:
- unsafe edits reach runtime or review
- AI-generated patches drift without proof
- developers repeat the same structural corrections
- reviewers cannot see why a change happened
- debugging loops expand because mutation had no evidence trail

## The Product

PREFIX Python is governed Python transition infrastructure.

It evaluates a change as a structural transition request:

human intent -> bounded structural analysis -> admissible continuation mapping -> deterministic transition governance -> legality evidence -> proof-bearing mutation or refusal.

Runtime support for rc2 is CPython `3.12.x` only. Python `3.11`, `3.13`, and `3.14` are outside the claimed release boundary, and Python `3.13` and `3.14` require separate AST authority catalogs before support can be claimed.

## The Four States

**APPLY**

One lawful continuation exists. PREFIX applies a bounded governed mutation, validates parse/reparse, and records proof.

**ADVISE**

Bounded continuations exist, but automatic mutation is not authorized. PREFIX ranks them deterministically and mutates nothing.

**ANALYZE**

The structural boundary can be explained, but safe mutation is not proven. PREFIX reports the boundary and mutates nothing.

**REFUSE**

The transition is unsupported, unsafe, or outside the bounded Python surface. PREFIX refuses deterministically and mutates nothing.

## Proof And Replay

Accepted mutations carry:
- governing law
- legality score
- continuation graph
- witness root
- receipt inspection
- deterministic replay
- rollback readiness where valid

If PREFIX mutates, the mutation is lawful, bounded, explainable, and replayable.
