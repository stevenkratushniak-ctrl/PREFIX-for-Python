# CATEGORY POSITIONING

## Category Claim

`PREFIX for Python` is a deterministic Python prefix layer for bounded correctness.

## What Category It Rejects

It is not:

- an AI copilot
- autocomplete software
- best-effort fixer
- probabilistic repair system
- commodity plugin
- ordinary linter

## What Category It Creates

It sits closer to:

- a legality layer
- a correctness membrane
- an edit-to-execution enforcement boundary
- a deterministic mutation appliance

## Why This Category Matters

The market already has many tools that suggest, rank, guess, and improvise.

`PREFIX` distinguishes itself by refusing to guess.

That means the product boundary is defined by:

- finite admissible error spaces
- singular lawful correction
- explicit refusal under ambiguity
- replayable evidence
- bounded trust

## Positioning Language

Preferred language:

- deterministic Python prefix layer
- bounded Python correctness
- refusal as a success state
- proof-bounded mutation
- local-first trust
- receipts, rollback, and replay

Avoid:

- assistant
- helper
- smart fixer
- AI coding companion
- productivity magic

## Premium Signal

Category ownership requires premium posture.

Cheap pricing would imply shallow trust.
Premium pricing reinforces that this is a correctness-control product with operational consequence.

## Release Signal

Category ownership also requires release discipline.

The first public-facing release should feel:

- selective
- calm
- high-trust
- operator-first

That is why the correct initial posture is a controlled founding-operator program rather than a broad utility launch.
