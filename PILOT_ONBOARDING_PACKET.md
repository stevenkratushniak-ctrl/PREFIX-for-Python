# PILOT ONBOARDING PACKET

## Welcome

You are receiving access to `PREFIX for Python` through a Controlled Operator Release.

This is a 30-day evaluation of a deterministic Python prefix layer for bounded correctness, available to selected engineering teams with proof-driven onboarding.

## What Makes PREFIX Different

`PREFIX` is deterministic Python transition infrastructure.

It does not guess.
It does not improvise.
It does not rank possible repairs.

It either:

- applies one lawful deterministic correction
- or refuses

## First-Day Sequence

1. Install from the canonical release bundle.
2. Run the deterministic correction demo.
3. Run the refusal demo.
4. Inspect a receipt.
5. Replay a prior accepted correction.
6. Review the support and feedback workflow.

## What To Look For

- whether behavior feels deterministic
- whether refusal is understandable
- whether receipts and replay increase confidence
- whether the product makes structural Python transitions easier to trust and review

## What Not To Expect

- broad speculative repair
- semantic code generation
- approximate mutation
- best-effort correction

## Operator Mindset

Evaluate the product as correctness infrastructure.

The most important questions are:

- Do you trust what it changes?
- Do you trust what it refuses?
- Can you explain what happened after the fact?
