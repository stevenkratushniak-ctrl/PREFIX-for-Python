# PREFIX Governance Appliance Hardening Report

## Scope

This pass keeps PREFIX Python-only and deterministic. No new semantic mutation authority was added. The work strengthens how the runtime and VS Code extension expose lawful transition governance.

## Runtime Posture

PREFIX is framed as deterministic structural governance for Python transition admissibility.

The operator-facing vocabulary is:
- transitions, not fixes
- governed mutations, not repairs
- admissible continuations, not suggestions
- structural legality analysis, not warnings
- refusal boundaries, not failure states

## VS Code Operator Surface

The extension now emits a true WHY surface for each engine outcome.

The surface includes:
- outcome state and lane
- governing law
- admissibility class
- surface class
- structural locality
- mutation scope
- continuation cardinality
- legality score
- boundedness proof
- ambiguity proof
- idempotency proof
- AST-distance explanation
- replay path
- witness lineage
- continuation graph hash
- structural witness hash
- candidate and mutation structural deltas

The extension also exposes `PREFIX: Show Last Transition Governance Surface` so an operator can reopen the latest local evidence packet without rerunning mutation.

## Mutation Authority

No APPLY rule was broadened.

ADVISE remains non-mutating.

ANALYZE remains non-mutating.

REFUSE remains non-mutating.

The new surfaces explain why these boundaries hold; they do not bypass them.

PREFIX now presents more like a legality appliance than a code assistant. It does not claim to understand intent. It governs bounded Python structural transitions and exposes the evidence behind each outcome.
